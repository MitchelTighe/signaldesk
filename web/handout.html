SignalDesk

Evidence before action.
A hypothesis you can inspect. A pause you can trust.

Small storage teams running LTO tape libraries need a useful first hypothesis without losing the source or the uncertainty. SignalDesk connects a drive ticket to its TapeAlert flags, SCSI sense data and library status, and to authored runbooks whose steps cite public documentation (sg3_utils, mtx, mt-st, LTFS, T10). It executes zero remediation: no robot moves, cleanings or resets.

A one-minute inspection

  1. Open site/index.html; start the walkthrough.
  2. H05: a drive asks for cleaning; inspect the TapeAlert evidence and the clean-then-re-verify runbook.
  3. H35 / H36: library and drive disagree after a load timeout; a log page that cannot be read.
  4. D16–D18: error, rejected source, not run.
  5. Switch models and theme; download the evidence.

What is real

Working UI, independent validator, guarded adapter, source checks and exporter. Three hero scenarios captured from an emulated mhVTL library (open source), sanitized; the rest are synthetic. Eight tape failure families. No API key is needed for replay.

What remains unproven

Behaviour on real drive hardware, external usability, production reliability and time savings. Emulated captures are not real drives, and same-author synthetic scenarios are not independent validation.
